# I — Instruction
## Le premier pilier du Framework [[ICA]]

---

## Définition

**L'Instruction c'est QUI est l'agent et COMMENT il se comporte.**

C'est la personnalité permanente du système.
Ce qui ne change jamais entre les sessions.

```
L'Instruction répond à :
→ Quel est ton rôle ?
→ Quelles sont tes limites ?
→ Quel est ton ton, ta façon de communiquer ?
→ Ce que tu ne feras JAMAIS ?
```

---

## Les 5 éléments d'une bonne Instruction

### 1. Le Rôle (qui tu es)
```
Tu es un [titre] spécialisé en [domaine].
```

### 2. Les Responsabilités (ce que tu fais)
```
Tu analyses...
Tu produis...
Tu coordonnes...
```

### 3. Les Limites (ce que tu ne fais PAS)
```
Tu ne touches JAMAIS au code.
Tu ne prends pas de décisions créatives.
Tu ne travailles pas seul sur une tâche qui appartient à un autre.
```

### 4. Le Standard (ta référence qualité)
```
Ton niveau de référence : [standard du domaine].
```

### 5. Le Format de Communication
```
Ton format de réponse : direct, structuré, en français.
```

---

## Ce que l'Instruction N'EST PAS

❌ L'Instruction n'est pas la connaissance technique → c'est le [[C]]
❌ L'Instruction n'est pas la liste des outils → c'est le [[A]]
❌ L'Instruction n'est pas le contenu du projet → c'est le [[C]]

✅ L'Instruction c'est uniquement : QUI + COMMENT

---

## Erreurs fréquentes

**Erreur 1 — Instruction trop longue**
```
❌ Un CLAUDE.md de 500 lignes
✅ 50 lignes bien choisies — le reste va dans les skills et agents
```

**Erreur 2 — Mélanger I et C**
```
❌ "Tu es un expert qui sait que notre stack est Flask + SQLite..."
✅ INSTRUCTION : "Tu es un développeur Flask senior."
   CONNAISSANCE : "Notre stack : Flask, SQLite, Railway."
```

**Erreur 3 — Pas de limites explicites**
```
❌ Oublier de dire ce que l'agent ne fait PAS
✅ Chaque agent a ses interdictions claires
```
